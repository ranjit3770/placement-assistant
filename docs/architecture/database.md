# M2 physical persistence specification

PostgreSQL 17 is the validation target. SQLAlchemy 2 typed mappings describe tables;
Alembic revisions freeze the physical schema independently of later model changes.
No migration seeds an institutional policy or implements eligibility calculations.

All tenant tables use UUID primary keys, a unique `(institution_id,id)` pair and
composite foreign keys for tenant-owned references. IDs are generated by the
application (`uuid4`) with a PostgreSQL `gen_random_uuid()` fallback for imports.
UTC-aware timestamptz stores recorded and effective instants. NUMERIC preserves
decimal values; JSONB holds schema-versioned definitions/snapshots, not executable code.

Every tenant row has provenance: source type/reference, verification state,
recorded timestamp, optional scoped actor, correlation UUID and correction reason.
Revision and event tables add positive sequence/version numbers and unique parent
keys. Reference rows and versions cannot cascade-delete historical records.

Checks enforce numeric bounds, academic presence states, compensation shapes,
known enum values, hash format and JSON object shapes. Composite relationship keys
also enforce matching company/role/drive, student/year/declaration and decision/
criterion. PostgreSQL triggers protect append-only records, published child rules,
grade-scale bounds and completed decision bundles. GiST exclusion constraints
prevent overlapping activation intervals; `btree_gist` is a migration prerequisite.

Repositories own scoped reads/writes, never make eligibility decisions and never
commit independently. An async unit of work owns the transaction. Immutable
revision append operations serialize on the parent; repeated source event keys
are rejected rather than silently overwriting data. Reference seeding is idempotent.

M2 stores policy lifecycle/declaration/offer events; authorized workflows and rule
interpretation remain M3–M5. A declaration lock preserves its original drive
cutoff. Models store multiple declarations/events for future policy evolution;
no active dream exception or compensation conversion is inferred from their presence.

Indexes cover tenant IDs, scoped natural keys, parent/version, event timelines,
opportunity lookup, policy applicability and student decision history. FK indexes
are explicit where parent lookups are not already covered by a unique index.

Validation uses a dedicated disposable PostgreSQL service, never M1 volumes.
Fresh migration, repeat upgrade, schema comparison, reference seed, repository/
negative tests, downgrade/upgrade, clean database recreation and backup/restore
must all produce recorded evidence. M2 remains pending coordinator acceptance.
