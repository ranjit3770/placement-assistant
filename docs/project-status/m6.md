## Implemented increment: verified source foundation

- Contract v0.2 incorporates all five independent-review clarifications.
- Private local `DocumentStore`: exact bytes, bounded reads/writes, atomic
  create-without-overwrite, hash verification on every read and retry, no caller
  paths, no symlink reads, private directory permissions.
- Additive `rag_source_objects` model and migration `c86d410a6201` after the frozen
  migration head. Composite tenant/document/actor references, original-hash check
  trigger and UPDATE/DELETE prohibition. No existing tables altered.
- Staff-only matching-byte import and review service for existing M4 metadata;
  tenant-scoped repository, database-derived identity, idempotent concurrent
  registration and recoverable orphan-object behavior after rollback.
- Provider-independent integrity types: distinct hashes, Unicode artifact offsets,
  binding-transition guard, embedding-space identity, vector/manifest validation.
  These pure guards do not implement binding persistence or generation publication.

This is an internal service, not a deployed upload/retrieval API. The existing M4
document API still creates metadata only. Staff import preserves its original hash
and simulated key; the additive source row owns the actual storage reference.
No student source-read route is exposed before binding authorization is implemented.

## Remaining work and limitations

Next: persist immutable binding revisions/events with serialized approval/revocation,
then durable ingestion jobs. Still pending: upload API/MIME checks and parsing
sandbox; normalized artifacts/chunk persistence; concrete embedding/vector adapters;
transactional published-generation pointer; context resolution and PostgreSQL
candidate reauthorization; evidence APIs; real semantic benchmark and index recovery.

The local storage directory must be administrator-owned and inaccessible to other
writers. Storage-key separation is not user authorization. Files left after a SQL
rollback remain unreachable until a successful retry; automated orphan cleanup and
production retention/backup validation are not implemented. Do not deploy this
increment as a complete RAG feature or describe pure manifest checks as atomic
publication. Full M6 evidence, pinned implementation commit and independent
certification remain outstanding.

R1/R2 release certification is not inferred from M5 or from this M6 design.
